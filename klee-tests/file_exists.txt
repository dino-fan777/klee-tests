  cnstr_t file_exists(const char *fname) {
      long m = 0;
      for (unsigned i = 0; i < __exe_fs.n_sym_files; i++) {
          long name_match  = _EQ_(fname[0], (long)('A' + i));
          long not_deleted = _NEQ_(__exe_fs.sym_files[i].stat->st_ino, 0);
          m |= (name_match & not_deleted);
      }
      return m;
  }

  cnstr_t file_not_exists(const char *fname) {
      long in_domain = _GE_(fname[0], 'A') & _LE_(fname[0], 'Z');
      long exists     = file_exists(fname);
      return in_domain & (exists ^ 1);   /* flips 0<->1, no !/&&/||/?: anywhere */
  }

  Why every piece is safe:

  - The for loop: i < __exe_fs.n_sym_files compares two concrete integers (a local counter and a value fixed once at startup from --sym-files) — never symbolic, so this branch never forks. It just unrolls N times.
  - _EQ_/_NEQ_/_GE_/_LE_: plain comparison operators (==, !=, >=, <=). These always lower to icmp + a conversion — a value computation, never a branch, at any optimization level. No ambiguity here.
  - &, |, ^: bitwise operators, not &&/||/?:/!. There's no short-circuit semantics to lower into control flow — nothing for the compiler to turn into a br even at -O0, because these operators don't have "skip evaluating the other side" semantics in the first place.

  flow.

  The accumulator — starts at "doesn't exist" (0). It will get OR'd with a 1 the moment we find a registered, non-deleted file whose name matches fname[0]. This is the running result of the whole ite(A,1,ite(B,1,...0)) chain, computed as one value instead of nested branches.

  Iterates once per registered sym-file. __exe_fs.n_sym_files is the real count set by klee_init_fds() at startup, straight from whatever --sym-files N K that run used — not a hardcoded or passed-in number, so this automatically covers N=1 through N=26 without the function
  needing to know N ahead of time. Both i and n_sym_files are concrete integers (never made symbolic), so this loop condition is a normal, non-forking branch — KLEE just unrolls it N times like any ordinary C loop.

          long name_match  = _EQ_(fname[0], (long)('A' + i));
  'A' + i is the actual name of file i, per klee_init_fds's own rule (name[0] = 'A' + k) — not an assumption we're making, it's KLEE's own naming convention read back correctly for each index. _EQ_(a,b) is a == b, a pure comparison — fname[0] is symbolic, so this doesn't evaluate
  to a concrete true/false; it produces a new symbolic expression (an equality constraint as a value) without branching, because == alone never requires control flow — there's nothing to skip evaluating, unlike &&/||.

          long not_deleted = _NEQ_(__exe_fs.sym_files[i].stat->st_ino, 0);
  __exe_fs.sym_files[i] is that file's exe_disk_file_t entry — safe to index since i < n_sym_files is the loop's own bound. .stat->st_ino is one of the fields __file_delete() zeroes out via memset(f->dfile, 0, sizeof *f->dfile). So this reads as 1 (not deleted) normally, or 0
  (deleted) after a delete. Again just a comparison — no branch.

          m |= (name_match & not_deleted);
  & (bitwise AND) combines "name matches file i" with "file i is still alive" — both are guaranteed 0-or-1 values from comparisons, so & here behaves exactly like logical AND would, just without any of &&'s short-circuit/control-flow baggage. |= (bitwise OR-assign) folds that
  into the running accumulator — again a plain arithmetic op, not ||. After all N iterations, m is 1 if any registered, non-deleted file matched, 0 otherwise. This is the ITE-chain, fully unrolled and computed as pure arithmetic.

      return m;
  }
  Hands back the accumulated symbolic boolean — a single expression built from N comparisons and N-1 ORs, no forks introduced anywhere in this function.
